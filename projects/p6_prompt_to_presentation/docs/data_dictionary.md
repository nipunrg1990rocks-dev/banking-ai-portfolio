# Data dictionary and KPI definitions

All shipped data is **synthetic** and generated by `generate_data.py` with fixed seeds. "Ledgerline Bank" is fictional.

## 1. Operational risk dataset (`data/ops_risk_synthetic.csv`)

Grain: one row per `reporting_month × region × business_line × process × severity × root_cause` cluster. Jan 2025 – Sep 2026 (21 months), 3 regions × 4 business lines × 5 processes, about 8,750 rows.

| Column | Type | Required | Allowed values / range | Meaning |
|---|---|---|---|---|
| record_id | text | yes | unique | Cluster record id |
| reporting_month | YYYY-MM | yes | valid month | Month-end period |
| region | category | yes | APAC, EMEA, Americas | Booking region |
| business_line | category | yes | Retail Banking, Corporate Banking, Wealth Management, Markets Operations | Owner |
| process | category | yes | Payments, Trade Settlement, KYC Onboarding, Reconciliations, Loan Servicing | Process |
| transaction_volume | int | yes | 0 – 5,000,000 | Process-month volume, **repeated on every row of the process-month (non-additive)** |
| completed_on_time | int | yes | 0 – volume | Process-month count within SLA (repeated, non-additive) |
| exceptions | int | yes | 0 – 100,000 | Exceptions in this cluster |
| severity | category | yes | Low, Medium, High, Critical | Severity |
| root_cause | category | yes | 8 values (Manual keying error, Missing documentation, System outage, Static data mismatch, Late counterparty confirmation, Screening false positive, Process design gap, Vendor delay) | As recorded by the control owner |
| ageing_days | int | no | 0 – 730 | Age at month end (days to close if closed) |
| control_owner | text | yes | | Accountable role (no personal names) |
| risk_score | float | no | 0 – 100 | Residual risk score |
| loss_amount_inr | float | no | 0 – 5bn | Operational loss, INR |
| remediation_status | category | yes | Open, In Progress, Closed | |
| data_quality_status | category | yes | Pass, Warning, Fail | Source-system DQ flag |

### Seeded anomalies (for testing and the demo story)

| Anomaly | Where | Expected handling |
|---|---|---|
| Exception spike, High/Critical uplift, "System outage" driver | APAC Payments, Jul–Aug 2026 | Visible on dashboard and in Q3 vs Q2 commentary |
| Reconciliations deterioration, "Static data mismatch" | APAC, Q3 2026 | Appears in driver ranking |
| Ageing deterioration | Americas KYC Onboarding from Jun 2026 | 90+ day band grows |
| Large Critical loss (₹4.85 cr) | EMEA Markets Operations Trade Settlement, Sep 2026 | Appears on loss and high-severity slides |
| 3 exact duplicate rows | random | Quarantined |
| 2 missing `ageing_days` | random | Kept, disclosed as warning / "Unknown" band |
| `completed_on_time` > volume | 1 row | Quarantined |
| `region = "Apac"` | 1 row | Normalised to APAC, disclosed |
| `region = "LATAM"` | 1 row | Quarantined (unexpected category) |
| Negative loss, risk score 140 | 1 row each | Quarantined (out of range) |

`data/ops_risk_refresh_oct2026.csv` is the "modified dataset" for demo step D: it adds October 2026, restates APAC Payments Low-severity exceptions for September (+25%), and plants two invalid rows (month `2026-13`, severity `Catastrophic`) that the gate quarantines.

### Ops-risk KPIs

| metric_id | Definition | Aggregation rule |
|---|---|---|
| exception_rate | sum(exceptions) / sum(transaction_volume de-duplicated per process-month) | Ratio of sums; n/a when volume = 0; severity filter narrows the numerator only |
| on_time_pct | sum(completed_on_time) / sum(transaction_volume), both de-duplicated | Ratio of sums; unaffected by severity filter |
| high_severity_exceptions | exceptions where severity in High, Critical | Additive |
| open_exceptions | exceptions not Closed, in the latest month of the period | Point in time |
| ageing_band | open exceptions by 0-30 / 31-60 / 61-90 / 90+ days | Unknown band when blank |
| closure_rate | Closed exceptions / all exceptions in period | Ratio of sums |
| mom_movement | exception rate latest month − prior month | Percentage points |
| dq_completeness | non-blank optional cells / all optional cells; plus % rows flagged Pass | Ratio of sums |
| loss_inr | sum(loss_amount_inr) | Blanks excluded and disclosed |

## 2. Workforce roster (`data/workforce_roster_synthetic.csv`)

Same 33 source columns as the case-study resource tracker: `Sr No, Last Updated By, Team, Project, Category, Position #, Name, Gender, Country, City, Email-ID, Start Date, End Date, Functional Manager, Vendor, PO, Profession Category, Profession, Profession Role, Cost Center, Jan-18 … Dec-18, Clarity Band`. Monthly columns are FTE allocations (0–1). Names, vendors and position numbers are invented.

Curated tables after validation (names and e-mails are dropped – data minimisation; a person is a hashed `person_key` of Position # + Name):

* `people`: one row per unique person-contract with location, resource type, vendor, profession, dates, daily rate, total FTE, zero-allocation flag.
* `allocation`: one row per person-month with FTE and cost (FTE × 22 × daily rate).

Seeded features: two roll-off waves (end March, end September), India-heavy reduction, 20 contracts with zero allocation all year, one duplicate record, e-mails with spaces, untrimmed project / PO / manager text, non-standard profession category spellings.

Rate card where no daily rate is given: Band_11 = EUR 200, Band_9 = EUR 100 (as in the case study).

### Workforce KPIs

| metric_id | Definition |
|---|---|
| people_on_contract | Unique Position # + Name with Start ≤ as-of date ≤ End; as-of = min(period end, roster date) |
| people_allocated | People with allocation > 0 in the month |
| fte | Sum of monthly allocations |
| monthly_cost_eur | FTE × 22 working days × daily rate (EUR); no FX, tax or mark-up |
| tm_share | T&M people on contract / people on contract |
| women_share | People on contract with Gender F / people on contract |
| avg_daily_rate | FTE-weighted average daily rate in the month |
| vendor_concentration | External (T&M + Fixed Price) people on contract from the two largest vendors / all external |
| retention | Share of the base-month team still allocated each month |
| contracts_ending | People on contract grouped by end date |
| zero_allocation | Contracts whose monthly allocations are all zero |

The original case-study roster is **not** in the repository. `reconcile_case_study.py` reproduces 13/13 of the published deck figures from it when run locally.
