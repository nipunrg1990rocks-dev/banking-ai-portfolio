Ledgerline Banking Lakehouse

A Bronze, Silver and Gold data pipeline for a bank, built on Apache Spark and Delta Lake. It checks every source record, quarantines bad data with the reason, keeps the full history of customer risk ratings, and refuses to publish numbers that don't reconcile.

View the code on GitHub ↗ Read the project pack (PDF) ↗

Independent project built by Nipun Gupta with AI-assisted development tools. All customers, accounts and transactions are synthetic and describe a fictional bank. It is not affiliated with any employer.

The banking problem

Bad data becomes a misstated report

Source systems send files with missing amounts, duplicates and late re-sends. Customer risk ratings change, and overwriting them destroys the history auditors ask for. Reports built on that data can double-count a payment or miss an AML pattern, and nobody notices until a reconciliation breaks. This lakehouse treats data the way a bank treats its books: every record is accounted for, and a run that doesn't balance stops.

The synthetic data generator keeps an answer key of every defect, duplicate, re-send, risk-rating change and suspicious pattern it plants. The tests require an exact match. These checks confirm the design works as intended; they are not an independent benchmark.

Banking controls built in

Controls a reviewer would expect

  • Bronze must match the source manifest's record count and amount total
  • 18 data-quality rules: warn, quarantine with reason, or stop the run
  • Customer risk-rating history kept as SCD Type 2, never overwritten
  • An unreadable KYC rating defaults to HIGH, so no customer drops out of monitoring
  • Personal data hashed or masked in Silver and absent from Gold
  • AML alerts are candidates for an investigator, never decisions
