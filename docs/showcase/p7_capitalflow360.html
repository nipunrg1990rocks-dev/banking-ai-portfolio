CapitalFlow 360

A simulated back office that takes 500 trades across six asset classes from order to settled cash and reconciled books, with a test system that never trusts the code it is testing.

Code on GitHub Handbook (PDF)

Independent portfolio project, built with AI assistance on synthetic data. Venues, clearing houses and custodians are simulated; no real market connectivity, production pricing or regulatory claim. Not publicly hosted yet.

The operations problem

Trades rarely fail at the trading desk. They fail afterwards: an allocation a cent short, a settlement date on a holiday in one currency, an expired standing instruction, a self-approved amendment. Each is small, and each becomes a fail, a break or an audit finding. CapitalFlow 360 models those paths and proves which ones the platform catches.

Controls

  • Maker-checker on every economic change; a maker can never approve their own request
  • Idempotency keys on bookings and ledger postings, so a replay posts nothing twice
  • Version checks on amendments, so two users cannot overwrite each other
  • Append-only audit trail with a correlation id on every request
  • Lakehouse quality gate: a batch with more than 5% bad rows is held back
